# 2026-10-08

## World scripts: research and plan

Planned script conversion for worlds, worked out against a private test repository for world
conversion, where a converted world works in a Basis client except for its scripts. Branch
`world-scripts`; nothing released or committed.

- **Shape.** A translator in Watari keeps a world's UdonSharp sources with their guids, adds only
  `partial`, compiles them in their own assembly, generates dispatch, variable access and sync
  code from the compiled types, and runs Basis's Cilbox script check, excluding and reporting
  what fails. A separate runtime package of `[Cilboxable]` classes implements the Udon API on
  Basis under the same namespaces, written only from VRChat's public docs and the MIT UdonSharp
  repository. Watari and the runtime package never reference each other's code; generated code
  names runtime types and checks a contract version.
- **Modes.** A "Scripts" category with Convert (needs the runtime package), Remove (static
  world, sources kept uncompiled for reference; the default without the runtime package) and a
  creator's own port. Every script is reported either way.
- **Research written down.** `research/udon-world-scripting.md` (UdonSharp's C# subset, storage
  in 1.x, names and events, networking semantics including ownership per GameObject, legacy
  versus `[NetworkCallable]` events, late joiners, `FieldChangeCallback` seeing the old value)
  and `research/cilbox-for-converted-scripts.md` (export, allow-list, language limits, lifecycle,
  the Basis APIs a script reaches, and catalog statements found wrong).
- **Sources not used.** The VRChat SDK packages and ClientSim are under VRChat's SDK licence,
  which forbids derivative works and reverse engineering. Facts from them stay out of this
  repository.
- **Found in Basis, not ours to fix:** the Cilbox API catalog says `LateUpdate` is not forwarded
  (it is), names a `BasisTeleportMode.Instant` that does not exist, says
  `GetComponent<BasisNetworkShim>()` adds the shim (only `SafeUtil.MakeNetworkable` does), and
  shows `+=` on `UnityEvent` fields.

## Runtime package and spike

- The runtime package exists as `basis-udon` (`com.yuna0x0.basis.udon`, local only, MIT), with its
  own `agent/` folder; symlinked into the Basis clone. AGENTS.md here now lists it under "Related
  repositories".
- Spike results are in `research/cilbox-for-converted-scripts.md` ("Measured 2026-10-08"). Two
  findings constrain the translator: an abstract method fails the box, and a generic method fails
  the export of the whole scene, so scripts with either must not pass through unchanged. Hooks on
  a base class are not called for subclasses, which decides how generated code reaches
  per-frame work.
- Decided with the user: a scene driver in the runtime package does per-frame and start-up work
  (basis-udon decision 0004), so generated code adds no `Update`/`Start`. The translator rewrites
  `abstract` methods to `virtual` with a default body, excludes and reports scripts with generic
  methods, and warns on `foreach` over `Transform` children. Cilbox fixes upstream may be proposed
  later as a separate track.

## Translator pipeline

- `Pipeline/UdonScriptTranslator.cs`: rewrites each source, compiles on the side with
  `AssemblyBuilder` (`COMPILER_UDONSHARP` defined), sets aside files that fail and recompiles until
  the rest compiles, excludes classes with generic methods, reads the compiled types, generates
  companions, compiles sources and companions together, and only then writes the scripts (with
  their original `.meta`), companions and an asmdef whose references are read off the compiled
  result. Checks basis-udon's `UdonContract.Version` first.
- `Mapping/UdonSharpSourceRewriter.cs` also neutralises `UNITY_EDITOR` in preprocessor lines (an
  upload build, as UdonSharp makes one), reports editor-only blocks as dropped, and rewrites
  `GetComponent(typeof(T))` to `GetComponent<T>()` (Cilbox cannot load `typeof`).
- Codes added: `script.compile.excluded`, `script.compile.dependsOnExcluded`,
  `script.genericMethod.excluded`, `script.editorCode.dropped`, `script.editorScript.notCopied`,
  `script.abstract.virtual`, `script.foreachTransform`, `script.sync.anyAsManual`,
  `script.sync.typeDropped`, `script.hook.inheritedPrivate`, `script.trigger.conflict`,
  `script.runtime.missing`, `script.runtime.unsupportedVersion`, `script.companion.failed`,
  `script.translated`. Not yet in `docs/docs/reading-the-report.md`; added before any release.
- Tests: rewriter, generator, and an integration test that runs the translator on hand-written
  scripts (skipped without basis-udon). Suite 410 of 410 with basis-udon's tests.
- Run on two real inputs from the private test repository (sources in a temporary folder):
  a world converts 53 of 86 scripts, a pen prop 2 of 15; the rest are traced to runtime gaps.
- Per the user: no upstream requests to Basis or Cilbox for now.

Next: the Cilbox load check after Unity compiles the written scripts, then the scene step.

## Semantic fixes move to basis-udon's IL post-processor

- basis-udon decision 0007: Cilbox's differences from Udon (shared struct boxes, `bool[]`, float
  `%`, unsigned to float, null casts, `char` calls, NaN branches, enum printing, checked casts,
  first `OnEnable`) are fixed by an IL post-processor in basis-udon, not by the translator, so
  hand-ported scripts get them too. The translator keeps the source rewrites that must happen
  before compiling (`partial`, `abstract`, `typeof`, `GetComponent` routing). The companion
  generator will declare `__udonOnEnableRan` on scripts with `OnEnable`; its `Awake` raises the
  first `OnEnable` once.
- Pattern counts on the real inputs are in basis-udon `research/api-coverage.md`.
- The report will list each rewrite per script (they are invisible in the source).
- `docs/versions.md` will gain UdonSharp and Cilbox rows (roadmap).
- Companion contract 3: type ID and name constants (`UdonCompanionGenerator.UdonTypeId`, SHA-256
  of the full name as UdonSharp computes it), the rewriter turns `GetUdonTypeID<T>()` and
  `GetUdonTypeName<T>()` into `T.__UdonTypeIDConst`/`__UdonTypeNameConst`, and scripts with
  `OnEnable` get the first-`OnEnable` flag and `Awake`. New code `script.onEnable.firstDropped`
  when the script declares `Awake` itself. `Awake` added to the hooks read from compiled types.
- Tests: 380 of 380.
- Unity 6000.7 marks `UnityEditor.Compilation.AssemblyBuilder` obsolete (CS0618: "This feature is
  being deprecated and will be removed in the future. Similar functionality can be achieved using
  the Roslyn compiler"). Replaced, per the user (no obsolete APIs): `Pipeline/SideCompiler.cs` runs
  the Roslyn `csc.dll` and .NET host that ship in the editor (the ones Bee runs for Unity's own
  compilation, found under `EditorApplication.applicationContentsPath`), with references and
  defines from `CompilationPipeline` (the runtime assembly's `allReferences`,
  `compiledAssemblyReferences`, `defines`, and `GetSystemAssemblyDirectories`), and parses its
  output into `CompilerMessage`s. Suite 390 of 390 on it.
- Corpus run (about 50 open-source UdonSharp projects, private and untracked) found two bugs:
  - the translator never finished when every source was set aside (`AssemblyBuilder` refuses an
    empty file list, so the callback never came); it now finishes with nothing translated.
    Test `FinishesWhenEverySourceIsExcluded`.
  - companions declared `public partial class`, which conflicts with a non-public source class
    (CS0262); the companion now omits the accessibility modifier.
- No obsolete or unsupported APIs (per the user): Unity's CoreCLR-readiness analyzer flagged
  `AppDomain.GetAssemblies()` (UAC0005) and `Assembly.Load(byte[])` (UAC0020, "loads assembly
  into non-Unity AssemblyLoadContext and is not supported"); both now use
  `UnityEngine.Assemblies.CurrentAssemblies` (documented from 6000.5, the package's minimum).
- Regex rewriting replaced, per the user's question about Roslyn. Decided against bundling Roslyn:
  type-dependent rewrites moved to basis-udon's IL post-processor (component lookups, `typeof`,
  type IDs, enum attribute, abstract methods), and `partial` is inserted where the compiler reports
  CS0260 after compiling the companion beside the source (`UdonSharpSourceRewriter.InsertPartial`).
  What remains as text is the `UNITY_EDITOR` swap in preprocessor lines (whole lines, exact) and a
  declared-name scan used only to trace errors to files. Bundling Roslyn would add about 6 MB of
  `Microsoft.CodeAnalysis` DLLs, which other editor tools also bundle (a duplicate precompiled
  assembly name fails Unity's compile), and would not remove any remaining case.
- Companions declare static component-lookup helpers per class (`__UdonInChildren`,
  `__UdonAllInChildren`, `__UdonInParent`, `__UdonAllInParent`, `__UdonAll`); type ID constants are
  inlined in the companion's overrides. Codes removed: `script.abstract.virtual`,
  `script.foreachTransform`. The post-processor's per-script change list still has to reach the
  report (open).
- Tests: 375 of 375.
- Side compiles now reference every project assembly that goes into a player build (TextMeshPro,
  UI and so on), as `AssemblyBuilder` did; define `UDONSHARP` and `VRC_SDK_VRCSDK3` besides
