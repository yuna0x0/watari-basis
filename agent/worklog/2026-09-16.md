## The Jiggle Physics dependency was one patch version off

Declared 16.0.0 since decision 0010; Basis has shipped 16.0.1 since July. A VPM client matches an
embedded package against a bare version string exactly, checked in vrc-get's resolver and with a
scratch project, so every install of Watari into a stock checkout warned of a conflict on that one
package. Now 16.0.1. The versions page says the Basis row stands for the two bundled targets too;
they are not rows of their own because their version numbers do not move between commits.

## An avatar that reads as empty now says why

A user reported that the converter could not find a descriptor that was visibly there. The
window showed a humanoid rig, nothing else, and no warning. Three states produce that: a prefab
file stored in Unity's binary form (reproduced here by saving a humanoid prefab with the project
on Force Binary; the text scan returns nothing and the .vrm route reads real types only),
components added on the scene object and never applied, and a selected object with no prefab
link over instances that still have one. Each is a warning now, with the fix in the message.
One fact shapes the messages: Unity refuses to save a prefab that carries a missing script, so
none of the three can be repaired inside a Basis project; the switch to Force Text, or applying
the overrides, has to happen where the VRChat scripts are installed. The binary fixture is a 5 KB
prefab of two objects saved that way; it imports in any project regardless of the setting.
Reading binary prefabs directly was considered and set aside: Unity's serialized form is
undocumented and version-specific, and the missing script leaves nothing for the object API
to expose, so the source project is the only place the data can be turned back into text.
