## Basis sync, Unity 6000.7.0b7

Synced the clone to upstream `developer` at d8b718d4f (178 commits, 6000.7.0b2 to 6000.7.0b7).
Reviewed the diff against everything Watari reads, writes or documents.

- Types, serialized fields, asmdef names, dependency versions, the avatar content allow-list,
  EditorOnly stripping, validator bone rules and `BasisTransformMapping` are unchanged.
- The constraint and authored motion solvers moved into `com.basis.constraints` and
  `com.basis.authoredmotion` (24edd8e7b). The components Watari writes stay in `com.basis.sdk`.
  `com.basis.setup` was deleted (ec088697a); Watari's docs never referenced it.
- New runtime writers of face blendshapes: HVR Comms' `AutomaticFaceTrackingInjector` adds
  Automatic Face Tracking to avatars with ARKit or Unified Expressions shapes or eye bones, and its
  `BlendshapeActuation` sets matched shapes to 0 when tracking stops or the component is disabled.
  Vixxy writes a value only when it changes, so a toggle's shape stays at 0 until the toggle
  changes. `BasisIdleExpressionDriver` adds on top of smile, joy, surprise and sad shapes. Both are
  in `limitations.md`. A wearer setting overrides the eye look range locally.
- Standalone builds use CoreCLR, Android and iOS IL2CPP.
- Cilbox (11747954a): `InterpretIID` became `CilboxClass.InterpretMethod`; basis-udon updated.
  Read from code, not measured: a clone of a loaded scripted object never loads (`P:345`), and a
  method on an unresolvable type no longer fails the load (`C:2516`). Recorded in
  `research/cilbox-for-converted-scripts.md`, which was rechecked at d8b718d4f.
- Docs corrected: `limitations.md` still said Basis had no per-avatar eye limit (stale since
  0.10.0), and the OSC paragraph and a planner comment predated the injector.

## Source versions

- VRChat SDK 3.10.6: face tracking on the descriptor. `lipSync` 5 was reported as not blendshape
  based and `eyelidType` 3 as no eyelids; both now have their own codes, `enableFaceTracking` is
  reported, and `eyeGazeMode` 1 skips the eye range measured from bones. Constraint
  `SmoothingFactor` is reported. No script identity changed.
- Not reported, measured: expression parameter bit width, lerp duration and signed
  representation; contact receiver material writes. Not checked: a Bool menu control with value 0
  (allowed again by the 3.10.6 menu editor) in `ToggleToVixxyMapper`. Not recognised: the new
  `VRCAnimatorFaceTrackingBlendshapesSet` state behaviour, in controllers only.
- UniVRM 0.131.4: the importer accepts a spring bone limit only with `specVersion` `1.0`, and
  0.131.3 exported `1.0-draft`, so those limits are dropped on import (`vrm.md`). The look-at
  change is runtime only.
- VRCFury 1.1442.0: `ArmatureLink.LinkTo` became the shared `ObjectReference` with the same
  fields; Full Controller gained `overwriteLocomotion` and face tracking fields, the latter now
  reported. VRCFury's global parameter list gained `UserEyeTracking` and `UserFaceTracking`; not
  added to `VrchatBuiltInParameters` without a controller that uses them.
- Modular Avatar 1.18.7, NDMF 1.14.8 and Dynamic Bone 1.3.4 are the newest stable releases.
