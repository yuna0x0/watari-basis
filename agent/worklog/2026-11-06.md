## Issues on scene instances

Four reports from one user, against 0.12.2, on a scene holding several variants of one avatar
with clothing prefabs and many instance overrides. All four were valid in 0.13.1.

- Index paths: `TryTranslate` and `HierarchyLocator.TryLive` replayed a sibling-index path from
  the prefab asset on the scene instance. A child added ahead of the prefab's own, or a removed
  one, shifted every later index: rigs were skipped, and two were written onto other objects.
  `PrefabCorrespondence` now follows the instance's prefab links level by level; the index path
  stays for hierarchies that are not instances. An object removed on the instance is reported as
  `apply.removedOnInstance`.
- Old Auto armature links: VRCFury's upgrade (`ArmatureLink.Upgrade`, version 7) merges the
  whole tree when any skinned mesh outside the link root is bound to it. Watari required a mesh
  bound both inside and outside, so clothing whose mesh sits beside its armature moved only its
  root. Links before version 7 also take alignment from Keep Bone Offsets (Auto follows the merge
  decision), which Watari read as off. Not handled: the legacy fixed `skinRewriteScalingFactor`.
- Eye position: Basis measures `AvatarEyePosition` in metres from the root with its scale
  (`BasisAutomaticSetupAvatarEditor`) and takes the avatar's height from it at calibration. The
  view position is in the root's unscaled space, so a scaled root got too tall an eye. The writer
  now converts on the target; the VRM path had the same fault through `InverseTransformPoint`.
- Suite: 402 green. Released as 0.13.2.

An issue form (`.github/ISSUE_TEMPLATE`) now asks for the report and the Watari, Basis and Unity
versions, the operating system and the install method.
