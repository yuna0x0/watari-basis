# 2026-09-17

## A copy built by VRCFury reads as an avatar without a menu

A user exported a VRCFury Editor Test Copy into a Basis project and got no toggles. Read from
VRCFury's source: the copy's controllers, clips, menus and parameters are written under
`Packages/com.vrcfury.temp/Builds/<avatar>`, which a unitypackage export leaves out; and the menus
and parameters are attached as sub-assets of a `BinaryContainer` marked `PreferBinarySerialization`,
so that file is binary whatever the project's setting. Unity does not re-save an asset whose
script is missing (checked: `ForceReserializeAssets` on a missing-script menu left the file byte
for byte), so nothing in a Basis project can turn that container into text. Reading it is not
possible here; the original avatar is what converts.

Two things were wrong on this side. The loader took the first script document in a file, so a
menu packed into a container with other assets could never be read even as text; it reads by file
id now, and the descriptor and submenu references carry theirs. And an unreadable or absent
menu, parameter or controller asset was silent; each is a warning naming the cause. On the
branch `vrcfury-build-output`, unreleased.

VRCFury ships no sample avatar. One prefab on this machine carries its components: an Armature
Link, a Blendshape Link and a Full Controller, serialized as managed references under `content`
and `references.RefIds` with a `type: {class, ns, asm}` per entry. A reader for those is a source
of its own, the size of the Modular Avatar one, and needs real content with Toggle features to
check against; none is at hand.
