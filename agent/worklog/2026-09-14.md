# 2026-09-14

## Source audit

Audited every reader, mapper and writer against the sources they claim to match: VRChat SDK
3.10.5 (decompiled `VRC.Dynamics`, `VRCSDK3A`, `VRCSDKBase`), UniVRM 0.131.2 and the VRM spec,
Dynamic Bone 1.3.4, Modular Avatar 1.18.7 with NDMF 1.14.8, and the Basis clone at a8e310938
(jiggle physics 16.0.1, HVR Basis Comms). Seven read-only passes, one per area, each verified
against code before anything changed. Findings fixed in this release are in the changelog under
Unreleased. The pattern behind most of them is the one `allowCollision` had: a field read for its
name rather than for what the runtime does with it.

Confirmed against code and fixed:

- PhysBone: root with one child is simulated (`childCount == 1` before Multi Child Type is read);
  spring curve inverted drag; grab needs `radius > 0`; `maxStretch` bounds bone length, not grab
  reach; curves sampled by index (VRChat) vs distance (jiggle); `isAnimated` means the rest pose
  follows animation, which jiggle always does; Hinge projects onto a plane.
- Dynamic Bone: no root means no simulation; radius 0 still collides as a point; elasticity is a
  per-tick lerp fraction (jiggle squares stiffness); stiffness is a displacement cap
  `2·length·(1−s)`; gravity is per tick without a time step and cancelled at rest; damping is
  the whole velocity; Update Rate scales elasticity; End Length 1 is jiggle's own tip.
- Constraints: VRChat forces `Locked` on in play, Basis unlocked snaps undriven axes to rest;
  LookAt roll is `-Roll` about the look axis in VRChat and `+Roll` in Basis; Basis normalises a
  lone source's weight; `CaptureRest` overwrote the planned at-rest pose; the retarget check
  compared a Transform id with a GameObject id.
- Descriptor and rig: Eye Look off leaves stale eyelid settings serialized; blink slot -1; Basis's
  validator requires Chest and Neck and warns on shoulders; head chop entries on the humanoid Head
  are skipped by `BasisLocalAvatarDriver`.
- VRM: the 1.0 tail joint's parameters are never read by UniVRM (`joints.Length - 1`), yet the
  importer writes defaults onto it; rotation and roll constraints copy a delta from rest, so a
  Basis rotation constraint needs the rest offset; 0.x clips are identified by preset, not name;
  presets leaked angle limit, stretch, soften, air drag, root stretch; cone limits unread;
  `VRMLookAt` (obsolete) has a `LateUpdate`.
- Menus and Vixxy: `saved` and `networkSynced` were read and dropped; a Vixxy control inside an
  avatar initialises only through `HVRAvatarComms`; two-choice activations read the ON entry
  only, so equal choices invert; object-reference curves (material swaps) were invisible; a
  non-looping clip holds its last frame in both Unity and Basis; Basis's menu presents a toggle
  only for values 0 and 1.
- Modular Avatar: `ParameterAssignerPass` assigns `__MA/AutoParam/<name>` to a toggle with no
  parameter; `Inverted` inverts the condition, not the value; the default comes from `isDefault`
  and `automaticValue`; `AvatarObjectReference` prefers `targetObject` and records paths from the
  avatar root; labels come from `label` then the object name; `ModularAvatarMenuInstallTarget`
  was unlisted; the Blendshape Sync and Parameters passes are VRChat-only.
- Everywhere: `m_Enabled` was never read.

## Variant overrides

Surveying for the Shape Changer work showed that a prefab variant's overrides were never read:
47 real prefabs override fields Watari reads (66 PhysBone, 28 Dynamic Bone, 312 Modular Avatar,
1 constraint lines), the user's own Shinano avatar prefab among them. `PrefabOverrides` reads
every PrefabInstance modification list in the scanned files and writes the values into the
inherited documents' lines before any reader runs, following stripped documents to the file that
defines them and repeating a list's last entry when a size override grows it, as Unity does.
Overrides on a scene instance are still not read (`limitations.md`).

Checked end to end on Shinano wearing the outfit's Shinano variant, headless: 21 blendshape
values written (19 on `Body_base`, 2 on the outfit's socks through the live hierarchy), 11
controls, 80 rigs; `fx.layersUnread` named the five gesture and AFK layers, `motion.motionTime`
the breast and hair sliders, `vixxy.overlap` the Corset and Toe_heels shapes three toggles share.

## Toggles that switch PhysBones, 0.8.1

The "measured gap" about clips enabling PhysBones was worse than described: an enable curve on
a script counted as an unknown curve, so the whole toggle was dropped as `vixxy.notSimple`,
its object switches included. Sugar's clothes-off clip: 10 object switches and 4 PhysBone
disables, all lost. Shinano's five hair toggles were in the same state. Now an enable curve on
a script becomes a switch on the jiggle rig written for the PhysBone on that object, and one
on a renderer a switch on the renderer, through the same activation mechanism motions use.
Any other component switch is left out and reported. Shinano: 13 controls instead of 11, the
Hair selector switching 8 rigs. The mistake was describing the symptom from memory instead of
reading one clip through the reader.

## Examined and declined: motion-time sliders

Shinano's Breast size and Hair length are radials driving a state's motion time; the report
names them under `motion.motionTime`. Converting them means sampling a clip along time, turning
its 12 stepped object switches into thresholds, and resolving material properties stored by
hash. That is interpreting the animator, not converting data, so it stays out. Two sliders on
one avatar, rebuildable by hand from the clip's end values. The other 42 motion-time states on
Shinano are gesture expressions driven by the built-in gesture weights, out of scope by design.

## Purchased fixtures found, not addressed

The avatars the tests read but the package does not ship moved into `Assets/_UserContent`, the
folder Basis ignores, so the Basis clone can track upstream with no local commit. Seventeen tests
carried the old fixed path and would have skipped silently. They now go through `LocalFixtures`,
which searches each folder of `Assets/_UserContent` and of `Assets` for the relative path and
returns null when nothing holds it.
